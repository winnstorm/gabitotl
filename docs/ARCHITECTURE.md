# GabitoTL architecture

Go module `github.com/winnstorm/gabitotl`. Stdlib first; third-party dependencies are
`gopkg.in/yaml.v3` (front matter), the Charm v2 stack (`charm.land/bubbletea/v2`, `lipgloss/v2`, `huh/v2`), used only by `internal/tui`,
`github.com/jackc/pgx/v5` (PostgreSQL driver, used only by `internal/memory/store/pgstore` and the test helper `internal/pgmanaged/pgtest`)
and `github.com/modelcontextprotocol/go-sdk` (the official Go MCP SDK, used by `internal/memory/server` (server and stdio bridge), `internal/memory/mcp` (the client transport) and their tests).

## Package layout

| Path | Responsibility |
|------|----------------|
| `cmd/gabitotl` | Thin `main`: calls `cli.Run`. No logic. |
| `internal/cli` | Subcommand dispatcher and commands (`install`, `migrate [gentle-ai]`, `doctor`, `restore`, `uninstall`, `cleanup`, `init`, `memory doctor|search|serve|server|token`, `scan [--root] [--json]`, `vcs status|branch`, `backup create|list|restore|prune`, `worktree add|list|remove`, `work start|update|status|overlap`, `memory use`, `who [--json] [--no-memory] [--no-worktrees]`, `session start|touch|end`, `runtime list|detect|plan|apply|verify|remove|set`, `import detect|run`, `persona print [--stats]`, `version`, `help`). `gabitotl` with no arguments onboards a project without `.gabitotl` (the full-screen installer on a terminal, the plain questions otherwise) and prints a short status in a configured project (it never opens the installer there; `gabitotl install` does); it never starts an agent. `memory server install|start|stop|status|logs|backup|remove` drives the managed PostgreSQL, `memory serve` runs the Memory MCP server, `memory token` manages its project-scoped bearer tokens, `memory mcp` is the stdio memory entry every runtime registers: it resolves the provider per call from the `.gabitotl/memory.md` of its project (`memoryRouter`: memory-mcp over HTTP, Engram through the CLI, a clear tool error without a project; D28) and `memory migrate engram` imports an Engram export; their hooks (`pgManagerFn`, `openStoreFn`, `signalCtxFn`) let tests inject a fake engine, an in-memory store and the shutdown signal. Takes an `Env` (stdin/stdout/stderr/cwd/TTY) so commands run in-process in tests; composition-root hooks (`installerEnvFn`, `installerRunnerFn`, `runtimeEnvFn`, `newProvider`) let tests inject a fake home, PATH and command runner. `work start|update` print the soft-lock OJO advisory (active-work files only, never blocking). `who` opens worktrees through `openRepo` and the memory provider through `openMemory`, and uses `ActiveWork` only when the provider has it (memory-mcp; Engram is skipped silently); `session start|touch|end` register, refresh and remove the active identity's session for any agent runtime (anchor: `--anchor-pid`, default the parent process) and are silent no-ops outside an initialized project (D27). |
| `internal/version` | Build metadata. |
| `internal/gabitotl` | Project layer: `Layout` (all `.gabitotl/` paths), Markdown + YAML front matter codec (`ParseDoc`, `RenderDoc`), typed configs, secret guard, `Init`, `DetectKind`, `FindRoot`. `MemoryConfig` is the merged view of the team-memory settings, which live in two files (D30): the committed `memory.md` (mode, provider, backend, project_key, team-reachable `url`) and the per-person `local/users/<id>/memory.md` (role, instance, token reference, postgres_connection, optional local `url` override). `LoadMemory` merges them (local wins; per-machine fields still in a legacy shared file are the fallback), `SaveMemory` splits them and moves legacy per-machine fields out of the shared file, keeping the body and unknown keys; a loopback address never reaches the shared file. `ActiveUserID` derives the id of the person (OS user, `GABITOTL_USER` overrides) here so this package needs nothing from `identity`. |
| `internal/identity` | Developer identity: slugged IDs, shared profile in `users/`, active identity derived from the OS user (`GABITOTL_USER` overrides; no identity file, no prompt). `Active` creates the shared profile silently when missing. Never stores emails. |
| `internal/memory` | Provider-agnostic memory contract: `Provider` (Search/Save/Update/SessionSummary/CurrentProject/Doctor), `Entry` with traceability fields, `Guard` (team mode requires `actor`; unknown authorship is `legacy`), `Factory`, relevance query builder (capped, never loads memory in full) and `Recorder` (honors `workflow.memory_after_work`). |
| `internal/memory/engram` | Adapter over the real `engram` CLI behind a `Runner` interface (tests use a fake). Search, Save, Doctor (`engram doctor --json`, read-only), `Projects()`, `Export()`. `Update`, `SessionSummary` and keyless `CurrentProject` have no CLI equivalent and return `ErrUnsupported`; the DB file is never touched directly. Traceability fields travel in a `**Label**: value` content trailer. |
| `internal/memory/mcp` | The Memory MCP client provider: a `memory.Provider` over a thin `Transport` (call a named tool with JSON args). Its default tool names (`memory_search`, `memory_save`, `memory_update`, `memory_session_summary`, `memory_current_project`, `memory_doctor`, `memory_active_work`) match the real server and a server test enforces it. `SDKTransport` is the real transport: streamable HTTP (bearer token read from an `env:NAME` reference on every request, falling back to the 0600 `memory-client.env`; plain `http://` only to loopback) or a stdio child process. Calls have timeouts, reads (and only reads) are retried once, and failures map to `ErrAuth`, `ErrUnreachable`, `ErrSchema`, `ErrRateLimited`, `ErrForbidden` or a `ToolError`. `FromConfig` builds the provider of `provider: memory-mcp` from `url` and `token` in `memory.md`. `Doctor` reports reachability, authentication, server schema and the project key. Ships an in-memory `FakeTransport`. No PostgreSQL access. |
| `internal/memory/store` | Persistence contract of the Memory MCP server: `Store` (save with upsert by `topic_key`, get, optimistic `Update` by `revision`, soft `Delete`, relevance `Search`, `Active` work listing, session summaries, `Doctor`, `Stats`) plus `TokenStore` (hashed API tokens). An actor is required on every write (`legacy` only for imports); every write is validated for NUL bytes and size-independent invariants in one place (`CheckEntry`). |
| `internal/memory/store/memstore` | In-memory `Store`: backs the server unit tests and is the reference the conformance suite holds the real store to. |
| `internal/memory/store/pgstore` | PostgreSQL `Store` over `pgx/v5` pooling. Embedded ordered migrations (`migrations/NNNN_name.sql`, `schema_version` table; 0002 project-scoped tokens, 0003 the import path) applied under an advisory lock, each together with its version row. Concurrency-safe upsert is one `INSERT .. ON CONFLICT` against the partial unique index on live `(project, topic_key)`; updates lock the row (`FOR UPDATE`) so the revision check is atomic. Search is a weighted `tsvector` (`simple` configuration: no stemming, no stopwords, so Spanish and English behave alike; title > topic/task > body) queried with sanitized prefix terms. The connection string never appears in logs, errors or reports. |
| `internal/memory/store/storetest` | The conformance suite run against every `Store`. |
| `internal/memory/server` | The Memory MCP server (official Go SDK). Seven tools, stdio and stateless streamable HTTP. HTTP auth is a per-user bearer token (`gbt_<id>.<secret>`; only the SHA-256 of the secret is stored, constant-time compare, immediate revocation) carrying a project allowlist or an explicit all-projects flag, enforced on every tool; the actor of every write is the token owner and a request naming another actor is rejected. `NewBridge` builds the stdio bridge from the same tool descriptors and forwards calls through a `Forwarder`; `--trusted-proxy-header` is an opt-in for the throttle address. Request/field size limits, per-call timeouts, per-user token-bucket rate limit, per-address throttling of failed authentication, structured logs without content or secrets, plain HTTP refused on non-loopback addresses unless a TLS proxy is declared. |
| `internal/pgmanaged` | The managed PostgreSQL: a dedicated labeled container, volume and network driven through the docker or podman CLI behind a `Runner`. See "Managed PostgreSQL isolation" below. `FakeEngine` is the in-memory engine used by every default test; `pgtest` gives opt-in tests an isolated database (`GABITOTL_TEST_DOCKER=1` throwaway container, or `GABITOTL_TEST_PG_DSN` with a schema per test). |
| `internal/memory/migrate` | `MemoryMigrator` + `Registry`, `Request`, `Report` and `ErrNoBackup`. Only a proven adapter is registered; every other pair returns `ErrNoTestedMigrator`. |
| `internal/memory/migrate/engrammcp` | The tested Engram to team-memory migrator: reads the official `engram export` JSON (schema VERIFIED/ASSUMPTION documented in the package), refuses without a non-empty safety backup, dry-run report, idempotent import keyed by source id through `store.Importer`, resume after interruption, count and content-hash verification, report without content. Never modifies Engram. |
| `internal/memory/providers` | Composition root: registers shipped providers in a `memory.Factory`. The only package that imports concrete providers. |
| `internal/scanner` | Layered, bounded project scanner (structure with file cap and skip list, README/docs, manifests to stack and commands, recent `git log`, main modules). Read-only and deterministic; `ProjectMap.ToEntry()` yields the `project-map` memory entry, including open questions for what cannot be inferred. |
| `internal/vcs` | Git layer behind a `Runner` interface (tests use temp repos and fakes, never a remote). Status and provider inference from `origin` (github, bitbucket, gitlab, azure-devops, git, local), task branches, Conventional Commits only (attribution trailers rejected, none added), push, and `Revert` (new commit; the only rollback). Every operation is gated by `VCSConfig.Permissions` (allow/ask/deny). History rewrite (force-push, `reset --hard`, amend, rebase) fails with `ErrHistoryRewrite` before reaching git. PRs go through `PRProvider`: `GitHub` (via `gh`) and a documented `Bitbucket` stub (`ErrNotImplemented`). |
| `internal/branding` | Leaf package (imports nothing from the project): the deterministic, offline LLM-attribution detector. Five classes (trailer, generated, header, boilerplate, footer), each needing a brand plus an authorship cue so plain technical mentions never match; `IsAIIdentity` separates AI identities from people who share a brand word. `Scan`, `Strip` (message text), `ScanFile`/`ScanPaths`, the skip rules (`.git/`, `.gabitotl/.bak`, binary, oversized), glob allowlist. Corpus of positive and negative cases in `testdata/`. |
| `internal/guard` | Authorship guard around Git: managed `commit-msg`/`pre-commit` hooks (ownership marker, chaining of a user hook as `<name>.gabitotl-orig`, `core.hooksPath` and worktree aware), scan sources (staged diff additions, diff against a ref, whole tree, read-only history audit) and the fixer (removes only pure-attribution lines, backup first, never rewrites history). |
| `internal/backup` | Local snapshots under `.gabitotl/.bak/<user>/<timestamp>_<task>/` with `manifest.md` (user, task, date, branch, base commit, files, reason). Copies only existing files; refuses paths outside the project root (including `..` and symlink escapes); never copies `.gabitotl/.bak` or secret-looking files (`.env*`, keys). `Restore` only restores manifest files and first saves current state in a `pre-restore` snapshot. `Prune` keeps a snapshot if it is among the newest `max_snapshots` OR newer than `max_age_days`. |
| `internal/coordination` | Team support (spec 8). `Worktrees` (over `vcs.Repo`): add/list/remove git worktrees at `<repo-parent>/<repo-name>-worktrees/<task-or-user>` (refuses temp dirs, never forces removal, never touches the main worktree). Advisory session registry: each live session writes `.gabitotl/local/sessions/<id>-<pid>.yaml` (user, anchor pid, started, last_seen, optional task/branch/areas/runtime); `Register`/`Touch`/`Unregister`/`Sessions`/`Notices`. Live means the anchor PID exists (EPERM counts) and `last_seen` is within 12 h; dead ones are pruned on read. Long-lived entry points (`memory serve --stdio`, `memory mcp`) anchor on their own PID and heartbeat; short-lived ones (`work start|update`) anchor on the parent. It informs, never blocks, and a write failure is only a warning (D26). `Who` merges this directory's sessions, the sessions in each other worktree's own `.gabitotl/local/sessions`, active-work files and shared-memory entries into `Presence` rows (scope `directory|worktree|remote`, source `session|work-file|memory`); the same user and task (or the same user and branch when one side has no task) is one row, the most specific source wins and fills only the gaps of the others; an unavailable source is a warning in the report (D27). Task files `.gabitotl/work/<user>/<task>.md` (front matter id/owner/status/branch/areas/files; body Completado/Falta/Próximo paso per spec 29) and `CheckOverlap`, an advisory soft lock over active-work files and memory search (memory failures become warnings; never blocks). |
| `internal/persona` | Output policy and the compact persona. `Classify` (new-project, feature, bugfix, refactor, maintenance, configuration, research; deterministic keyword heuristics, internal only). `Renderer`: small work (1-2 sentences) and long work (mandatory Qué hice / Progreso / Qué sigue; Ojo and TIP only when non-empty), a `Truncate` rule (whole sentences, else word boundary plus an ellipsis) and `ValidateSmall`/`ValidateLong`. `ShouldAsk(Risk)` / `DecideAlone` implement the question policy of spec 19. User-facing wording lives only in `messages_es-AR.txt` (es-AR, replaceable via `ParseMessages`); `persona.md` is the embedded system prompt (about 1400 estimated tokens, tested against a 1500 budget; it carries the "Noisy terminal" rule: a failing or noisy shell command is replaced by a short Python script under `.gabitotl/tmp/`) rendered with those messages by `Text`. |
| `internal/budget` | Context-budget monitor. Uses real token counts when the runtime reports them (`ReportTokens`), otherwise `EstimateTokens` (ceil(runes/4)). `Check` returns `Decision{ShouldSave, Message}` once per session when usage reaches the threshold (default 75% of the limit); state per person in `.gabitotl/local/users/<id>/session.md` (`New(layout, user, cfg)`). `Checkpoint` saves progress, decisions, next step and the session summary through `memory.Recorder` and returns the es-AR TIP only when memory really recorded it; failures re-arm the trigger and never block the user. |
| `internal/ownership` | Spec 38. Markdown sections wrapped in `<!-- gabitotl:start NAME -->` / `<!-- gabitotl:end NAME -->` with idempotent `UpsertSection`/`RemoveSection` (user content outside the markers is untouched). JSON/JSONC cannot carry markers, so `jsonedit` is a splice editor: it scans the document (comments, trailing commas) and replaces only the managed byte ranges (`Set`, `Remove`, `ArrayAdd/Has/Remove`), never re-serializing. A document it cannot scan, or a scalar where an object is needed, returns `*UnsafeError` (`errors.Is(err, ErrUnsafe)`) and the adapter proposes a manual action. `Store` keeps `~/.gabitotl/state.json` (injected dir): per file the runtimes that own it, sections, managed keys (with the previous value and a prune flag), hash before/after and version. |
| `internal/runtime` | Core adapter contract (spec 32): `Adapter` (`Detect`, `Inspect`, `Backup`, `Plan`, `Apply`, `Verify`, `RemoveGabitoConfig`, `ListModels`), `Registry`, `Env` (home, project root, state dir, env lookup, `LookPath`, `Exists`, clock: every adapter takes it so tests use temp fixtures), `Detection` (`installed`/`configured`/`detected-history` plus evidence signals) and `Action` (`CREATE`/`MODIFY`/`PRESERVE`/`REMOVE-AFTER-VERIFY`/`NO-ACTION`). `Plan` is pure. `ResolveRuntime(layout, user)` merges `.gabitotl/runtime.md` with the person's override `.gabitotl/local/users/<id>/runtime.md` (local wins; a legacy `.gabitotl/local/runtime.md` is read only when that file is absent, never migrated); `SetRuntime` writes only those files, so changing the model never touches persona, memory or workflow. A test fails if core code contains runtime names in conditionals. |
| `internal/runtime/engine` | Shared editing machinery used by every adapter: planners (`PlanSection`, `PlanKey`, `PlanServer`, `PlanItem`, `PlanForeignPersona`), `Apply` (CREATE/MODIFY first, verify, then REMOVE-AFTER-VERIFY), `Remove` (driven only by the ownership state, so uninstalling never removes what GabitoTL did not create, and shared files wait for their last owner), global `Backup` under `~/.gabitotl/backups/<ts>/<runtime>/` (touched files only). |
| `internal/runtime/claudecode`, `opencode`, `kiro` | The only packages that know file formats and binary names (formats verified against official docs, assumptions listed in each package doc). Claude Code: persona as a marked section of `~/.claude/CLAUDE.md` or project `CLAUDE.md`, memory MCP entries (`rt.MemoryFor`: the bridge, plus Engram's own when its binary exists) in `~/.claude.json` / `.mcp.json`, Gentle-AI persona conflict reported and retired only with `--migrate-persona`. | `internal/importer` | Read-only knowledge importers (Kiro `.kiro/*`, Gentle-AI state and managed-block detection, Engram detection and project counts through the T2 adapter, generic CLAUDE.md/AGENTS.md sections outside gabitotl/gentle markers). They return `Knowledge` items (decision, convention, architecture, task, command, constraint, tooling), skip secret-looking files and never modify the source. `imports.md` (`Registry`) records origin, date, content hash, what was imported and last review; an unchanged hash is not imported again. Gentle-AI and Engram are detected independently. |
| `internal/installer` | Installer logic, no printing (installer spec sections 3-5, 16-28, 38-49). Every dependency comes through `Env` (home, environment, `LookPath`, command `Runner`, clock, runtime registry, migrator registry, memory opener); `FakeRunner` records invocations for tests. Phases in order (`PhaseOrder`): `DetectPlatform`, `DetectProject`, `DetectRuntimes` (through the adapter registry), `DetectMemory` (Engram on its own, reported next to the team server as a separate check and never fatal when missing: binary, `ENGRAM_DATA_DIR`, `.engram/`, read-only `engram doctor` and `projects list`; topology warnings for a data-dir override, cloud/autosync, project config and identity mismatch), `DetectOtherHarness` (Gentle-AI via binary, `~/.gentle-ai/state.json`, installed agents mapped to registered runtimes), `BuildInventory` (`inventory.json`, never carries secrets, remotes or environment values), `BuildPlan` (pure; CREATE/MODIFY/PRESERVE/IMPORT/REMOVE-AFTER-VERIFY/NO-ACTION; install-time and retire-time actions kept apart), `CreateSnapshot`, then `Run` (memory server, migrate knowledge, configure runtimes, verify memory/project/runtimes, retire, report). | `internal/tui` | Full-screen installer (Bubble Tea, Lip Gloss, Huh v2), presentation only. `Backend` (detect, build plan, run) is its narrow view of `internal/installer`. Screens: detection and menu (adapted to what was found), details, memory ("Tu memoria está segura"), team memory ("Memoria compartida (recomendado para equipos)": host, client or stay with Engram; no engine means host is not offered), the Engram question (import, keep, start empty), one huh form per undetectable question (including the team URL, token variable name and a password prompt for the token), runtime checklist, persona-retirement confirmation (the exact blocks), plan (with details), live apply progress with rollback visibility, retire-Gentle-AI question (asked by the pipeline after verification), result with TIP. `Run` returns an `Outcome`; the apply runs in a goroutine that streams `installer.Event`s as messages, `ctrl+c` cancels its context and waits for the pipeline's rollback, and `finish` guarantees no apply outlives the program. Scrolling keeps the cursor line visible in 80x24 and below; `NO_COLOR` makes every style empty. Tests drive `Update` with messages against a fixture machine. |

## Dependency rule

```text
cmd -> cli -> identity -> gabitotl
          cli -> memory/providers -> memory/{engram,mcp} -> memory -> gabitotl
          cli -> memory/server -> {memory/store, memory}   (server tests also import memory/mcp, never the reverse)
          cli -> memory/store/pgstore -> memory/store -> memory
          cli -> pgmanaged -> memory   (reports reuse memory.Report)
          cli -> memory/migrate/engrammcp -> {memory/migrate, memory/engram, memory/store}
          memory/mcp -> memory (client transport; never imports memory/server or the stores)
          cli -> scanner -> memory
          cli -> vcs -> {gabitotl, branding}
          cli -> guard -> {branding, vcs, backup, gabitotl}
          gabitotl -> branding   (WriteFile refuses attribution)
          memory -> branding     (entries are stripped before any provider)
          cli -> backup -> gabitotl
          cli -> coordination -> {vcs, memory, gabitotl}
          cli -> budget -> {persona, memory, gabitotl}
          cli -> persona            (leaf: imports nothing from the project)
          cli -> runtime/all -> runtime/{claudecode,opencode,kiro} -> runtime/engine -> {runtime, ownership}
          cli -> importer -> {gabitotl, ownership}
                  runtime/* and importer -> core (never the reverse)
          cli -> installer -> {runtime, importer, memory, memory/engram, memory/migrate, vcs, identity, persona, gabitotl}
          cli -> installer/ui -> installer   (presentation depends on logic, never the reverse)
          cli -> tui -> {installer, installer/ui}   (the TUI never contains installer logic)
```

- Core packages (`gabitotl`, `identity`, `memory`, `vcs`, `backup`, `coordination`, `persona`, `budget`, `runtime`) never
  branch on runtime names (`if claude`, `switch runtime`). A runtime is an
  opaque string in `runtime.md`; `internal/runtime` has a test that scans core sources for runtime names in conditionals.
- Runtime-specific behavior (file formats, install locations, model names)
  lives only in adapters, behind interfaces owned by the core.
- Core depends on no adapter; adapters may depend on core.
- `persona` is a leaf (it must not import `budget`, which imports it); `vcs` and
  `backup` know nothing about memory; only `coordination` and `budget` touch the
  memory contract, and only through `memory.Provider` / `memory.Recorder`.
- External commands (`git`, `gh`) run only behind `vcs.Runner`; no other package
  shells out to a VCS. Tests use temp repos and fakes, never a real remote.
- User-facing Spanish wording (OJO/TIP, Qué hice/Progreso/Qué sigue, the
  long-chat TIP) lives only in `internal/persona/messages_es-AR.txt`.

## Project layer invariants

- Every write under `.gabitotl/` goes through `gabitotl.WriteFile` /
  `WriteFileIfMissing`, which run the secret guard first and replace files
  atomically. Only `env:NAME`, `keychain:NAME` and `native` references are allowed.
- `Init` is idempotent and never overwrites existing files.
- Per-person local state lives under `local/users/<id>/` so several OS users can share one directory; those dirs are created group-writable (0o775 before umask) and each person writes only their own files. `local/` must be group-writable on Linux (setgid) for this to work across users.
- Team-memory settings are split by owner: what every teammate needs is committed (`memory.md`), what is true of one machine is not (`local/users/<id>/memory.md`). Only references are stored in either file.
- `local/`, `.bak/` and `tmp/` are listed in `.gabitotl/.gitignore` and never shared.
- IDs used in paths (user, task) must be canonical slugs, so paths cannot escape their directory.

## Memory rule

The workflow depends on `memory.Provider` only. Concrete providers
(`memory/engram`, `memory/mcp`) are registered into a `memory.Factory` at the
composition root and are never imported by workflow code. Team mode requires an
`actor` on every saved entry; historical or unknown authorship is recorded as
`legacy`, never invented.

## Ownership and runtime safety

- GabitoTL never takes over a file it does not own. Markdown assets live in marked sections; JSON/JSONC assets are spliced in as managed keys recorded in `~/.gabitotl/state.json`. Removal restores the previous value of a key we overwrote, drops parents we created, and deletes files we created once they hold nothing else.
- Every `Plan` is pure; `runtime apply` takes a global backup of the touched files first. A Gentle-AI/Gentleman persona block is removed only after verification and only with `--migrate-persona`.
- Equivalent MCP entries (same command and args under any name) are never duplicated, and an entry GabitoTL did not create is never removed.
- Context budget (`context_limit_tokens`, default 200000; `context_threshold`, default 0.75) lives in `workflow.md` front matter; files without the keys keep the defaults (`budget.FromWorkflow`).

## Installer invariants

Each is enforced in `internal/installer` and covered by a test.

- **Snapshot first.** `Run` creates the global snapshot (`~/.gabitotl/migrations/<timestamp>_<source>/`: `migration.md`, `manifest.json`, `inventory.json`, `memory/engram-export.json`, `gentle-ai/state.json`, per-runtime copies of only the files the plan touches or the adapter inspects, the ownership state and the project files it may create) before any mutation. If the snapshot fails (unhealthy `engram doctor`, failed export) nothing was changed.
- **Retire only after verification.** Install-time actions and REMOVE-AFTER-VERIFY actions are applied in different phases. `retire` refuses (`ErrNotVerified`) unless every critical check passed; a failed verification rolls back before Gentle-AI is touched. The interactive "retire Gentle-AI?" question is asked only after verification. Managed persona blocks go through the adapters; Gentle-AI itself goes through its own `gentle-ai uninstall` (only `uninstall --all`, and only when every agent it manages is one GabitoTL replaces; otherwise it is not run, the plan and report print an OJO, and the user runs Gentle-AI's own uninstall manually). After retiring, everything is verified again; shared MCP entries that Gentle-AI removed are reconnected once. A failed Gentle-AI uninstall keeps the verified GabitoTL setup (status `partial`) and points to `gabitotl restore <id>`.
- **Engram is adopted.** Only official `engram` commands run (`doctor` before and after, `projects list`, `export` into the snapshot, `save` through the memory provider for imports); the database file is never opened and `~/.engram`, `.engram/` are never touched. A missing Engram is never installed or wired. Team memory (Engram to Memory MCP) is offered only when `migrate.Registry` has a tested migrator (`engrammcp`, registered by the CLI composition root) and the machine hosts the database; the safety export is the migrator's required backup.
- **Adopt, never install twice.** Existing tools, equivalent MCP entries and identical assets are adopted; a re-run with nothing to change (`Plan.Mutates() == false`) skips the snapshot and changes nothing.
- **Never remove what is not attributable.** User skills, secrets, credentials, repositories and `~/.gentle-ai/backups/` are never touched; uninstall is driven by the ownership state; `cleanup` only deletes completed snapshots, global backups and `legacy/` entries older than the retention (default 30 days) inside `~/.gabitotl`, after confirmation.
- **No secrets in reports.** Reports, logs, `migration.md` and `inventory.json` list paths, ids and counts only; remotes and environment values are never recorded.
- **Provider change.** Moving a project from Engram to team memory is the install pipeline with the provider fixed (interactive question, `memory use`): `memory.md` is part of the snapshot and restored byte for byte on any failure, the import is the tested migrator over the snapshot's safety export (no duplicates, source untouched), and the reverse direction is refused with `ErrNoReverseMigration` (D29).
- **Team memory.** The managed server is installed only after the snapshot; a rollback removes the container and network the run created and keeps the volume and credentials (a server that pre-existed is never touched); the 0600 token file is restored byte for byte; tokens and passwords appear only in the environment or 0600 files, never in `.gabitotl/`, reports, logs or snapshots. The memory provider is per project (`memory.md`), so the runtime registration does not depend on it: one bridge entry, plus Engram's own entry when its binary exists. The only retired memory entry is Engram's own once its binary is gone, and only if GabitoTL created it (ownership state) (D28).
- **Rollback.** On any failure after mutations start, `Run` removes what each configured adapter owns (ownership state) and restores every file in the manifest byte for byte, including the ownership state and project files created by the run. Gentle-AI and Engram stay intact. Knowledge already saved to memory is never deleted (reported). `gabitotl restore` reverts configs from a snapshot but never touches Engram or the project's `.gabitotl/`, and saves the current files first.
- **Two backup levels.** Global: `~/.gabitotl/{migrations,backups}` for agent configs. Project: `.gabitotl/.bak` for code. They never mix.
- **Non-interactive safety.** Without a TTY and without `--yes` the commands refuse to mutate; `--dry-run` prints the plan and changes nothing. The TUI needs stdin and stdout on terminals.
- **Cancellation.** `Run` checks the context between phases: a cancelled run is reverted through the normal rollback until verification ends. Retirement runs with a non-cancellable context (point of no return), so Gentle-AI's own uninstall is never killed half way.

## Managed PostgreSQL isolation

The Memory MCP server needs a PostgreSQL. GabitoTL never shares one with the user: `internal/pgmanaged` creates its own, and the guarantees below are enforced in code and covered by tests (a property test runs hundreds of random worlds against a fake engine; opt-in tests run the real engine).

- **Own resources only.** Container `gabitotl-memory-postgres`, volume `gabitotl-memory-pgdata`, network `gabitotl-memory-net`, all labeled `io.gabitotl.managed=true` plus a role label. Names must start with `gabitotl-`. Before any mutating command the target is inspected and acted on only if it carries the label, by container ID rather than by name.
- **Collisions refuse.** A resource with our name but without our label is a conflict: install, start, stop, backup, remove and logs all return `ErrNotManaged` with an explanation and change nothing. `Remove` never touches a foreign volume or network even when the container is ours.
- **Never the user's PostgreSQL.** Loopback only (`127.0.0.1`), default host port 54329 (the next free one is picked when taken, an explicit busy port fails), port 5432 is rejected, pinned image `postgres:17.11-alpine`. The environment handed to the engine drops every `PG*`, `POSTGRES_*` and `DATABASE_URL` variable, and nothing reads `~/.pgpass`.
- **Credentials.** A random 256-bit password in a 0600 file (`~/.gabitotl/secrets/memory-server.env`, directory 0700), outside every project. It reaches the container through the environment of the engine command (`-e POSTGRES_PASSWORD`), never as an argument. Everything user-visible refers to `env:GABITOTL_MEMORY_DATABASE_URL`.
- **Data is kept.** `remove` deletes the container and network and keeps the volume and credentials; `--purge-data` needs the volume name typed. Installing over a kept volume reuses its password; a kept volume without its credentials file is refused rather than overwritten.
- **Named instances.** `--instance NAME` gives a second instance its own container, volume, network and credentials file.
- **Docker address pools.** On a machine whose default bridge pools are exhausted, the network is created with a small explicit `10.213.x.0/28` subnet (the engine rejects overlaps; no other network is inspected).
